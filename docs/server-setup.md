# Конфигурация виртуальной машины

## 1. Параметры машины

Импортированная виртуальная машина называется `ubuntu-server`; внутри ОС установлено имя `devops-vm.devops.local`. По данным гостевой системы: 3,1 ГиБ RAM, 3 vCPU, виртуальный диск 25 ГБ, раздел `/` на логическом томе 11,5 ГБ. Снимок `01-clean-install` не создан. При попытке добавить файл конфигурации VirtualBox сообщил, что UUID уже зарегистрирован; следует использовать существующую запись машины.

## 2. Сетевые интерфейсы

В гостевой ОС подключены два адаптера. NAT `enp0s3` получает адрес `10.0.2.15/24`. Host-only `enp0s8` получает `192.168.56.101/24`; адрес адаптера Windows — `192.168.56.1/24`. Имя `devops.local` на хосте разрешается в `192.168.56.101`. TCP-подключения с Windows к гостевым портам 80 и 443 проверены через интерфейс Host-only.

## 3. Правило проброса портов

SSH доступен на хосте по `127.0.0.1:2222`; фактический порт SSH внутри гостевой системы — TCP/22. Порты 80 и 443 через NAT не проброшены: веб-доступ осуществляется через Host-only по адресу `devops.local` (`192.168.56.101`). Nginx перенаправляет HTTP на HTTPS. Сертификат самоподписанный; для проверки `curl` его нужно передать как доверенный CA-файл.

## 4. Учётные записи

Импортированная учётная запись `sa` (UID 1000) сохранена. Создан администратор `devops` (UID 1001), член групп `sudo`, `users`, `docker`. Для `devops` добавлен ключ Ed25519; каталог `~/.ssh` имеет режим 700, `authorized_keys` — 600. Парольная аутентификация SSH отключена. Полное переименование `sa` не выполнялось: процесс `systemd --user` (PID 1446) использует эту учётную запись.

## 5. Служба SSH

Служба слушает TCP/22 в гостевой ОС; внешний порт NAT — 2222. Дополнительный файл: `/etc/ssh/sshd_config.d/00-hardening.conf`.

- `PermitRootLogin no`
- `PasswordAuthentication no`
- `PubkeyAuthentication yes`
- `PermitEmptyPasswords no`
- `MaxAuthTries 3`
- `LoginGraceTime 30`
- `AllowUsers devops`
- `X11Forwarding no`
- `ClientAliveInterval 300`
- `ClientAliveCountMax 2`

Синтаксис проверен `sshd -t`, эффективные значения — `sshd -T`; служба перезапущена.

## 6. Межсетевой экран

UFW активен. Политики по умолчанию: входящие соединения запрещены, исходящие разрешены. Разрешены TCP/80 и TCP/443; для TCP/22 действует `LIMIT`. Правило порта указано для гостевого порта 22, поскольку NAT перенаправляет внешний 2222 на него.

## 7. Снимки состояния

Снимки `01-clean-install`, `02-keys-configured`, `03-ssh-hardened`, `04-nginx-https` и `05-docker-compose` не подтверждены. VirtualBox сообщил о повторяющемся UUID при попытке добавить файл конфигурации; не создавайте вторую запись и не меняйте UUID машины. Для снятия снимка найдите существующую запись ВМ в менеджере и используйте её.

## 8. Веб-сервер

Установлен пакет Nginx из репозитория Ubuntu. Конфигурация сайта: `/etc/nginx/sites-available/devops-site`, активная ссылка — `/etc/nginx/sites-enabled/devops-site`. Корень `/var/www/devops-site`, владелец файлов `devops`, режим каталога 755, файлов 644. Самоподписанный сертификат `devops.local` сроком на 365 дней содержит SAN `DNS:devops.local`: `/etc/ssl/certs/devops.crt` (644, root); закрытый ключ `/etc/ssl/private/devops.key` (600, root). HTTP перенаправляется на HTTPS. Хостовый `hosts` сопоставляет `devops.local` с `192.168.56.101`; TCP-порты 80 и 443 проверены с Windows через Host-only.

## 9. Контейнеризация

Docker Engine установлен из официального APT-репозитория Docker; версия сервера 29.9.2, Docker Compose 5.6.1. Учётная запись `devops` состоит в группе `docker`. Исходники проекта находятся в каталоге `app/` репозитория и развёрнуты на сервере в `/home/devops/app`. Шаблон `app/.env.example` хранится в Git, а файл `/home/devops/app/.env` создан только на ВМ и имеет режим 600. В `.gitignore` исключён `.env`.

Сервисы `app` и `db` подключены к сети Compose `app_backend`; PostgreSQL использует именованный том `app_db_data` и healthcheck `pg_isready`. Порт PostgreSQL 5432 не опубликован. Приложение слушает порт 5000 внутри контейнера и опубликовано только на `127.0.0.1:5001` хоста ВМ (`127.0.0.1:5001:5000`). Порт хоста 5000 был занят существующим процессом, поэтому выбран свободный порт 5001; приложение остаётся доступным снаружи только через Nginx.

В HTTPS-конфигурации Nginx для `/app/` задан `proxy_pass http://127.0.0.1:5001/`; заголовки Host, X-Real-IP, X-Forwarded-For и X-Forwarded-Proto передаются приложению. Завершающий `/` в `proxy_pass` удаляет префикс `/app/` при передаче запроса. Статические файлы сайта находятся в `site/` репозитория и размещены в `/var/www/devops-site`; права файлов — 644. Для передачи каталога `app/` методичка использует `rsync`, при его отсутствии на Windows применялся SCP.
